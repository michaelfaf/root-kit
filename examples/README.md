# Examples

Two sets, for two different questions.

## `fictional/` — what a finished set looks like

Five completed files for **Ridgeline Grounds Co.**, an invented commercial landscaping company in Fort Collins, Colorado. Every fact is made up. It exists to answer *"what does a correctly filled-in template actually read like?"*

Read it if you want to see: how the router stays short while routing to everything; how the tripwire section in `Business.md` gets written; what a named gate looks like in `About-me.md`; how numbers carry sources and dates; and how the deliberate duplication works — the two most important tripwires appear in both `Business.md` and the router, on purpose.

Ridgeline is nothing like the business this kit came from, which is the point. If the shape survives being ported onto a company with W-2 crews, seasonal snow contracts, and a completely different folder scheme, the shape is the portable part.

| File | Words |
|---|---|
| `AGENTS.md` | the router |
| `Home.md` | the map |
| `Business.md` | the model, including section 8 |
| `Goals.md` | targets and this quarter |
| `About-me.md` | the owner, at "seed plus a bit" depth |

## `live-vault/` — what a real one looks like after a year

The actual standing-instructions file and map from the Obsidian vault this kit was extracted from, copied unedited. Small B2B services business, run daily with Claude Code, in continuous revision for months.

It exists to answer a different question: *"does anyone actually live like this, or is this a nice idea?"* It's messier than the fictional set, it carries conventions specific to that vault, and several of its routes point at files you can't see. That's what a real one looks like. Read it for the density and the tone — how much gets said in how few words — not as a model to copy.

## How to use both

Read `fictional/` before you start, to know what you're aiming at. Read `live-vault/` after your first draft, to see how far the writing tightens up after a year of use. Copy neither.
